   `record_brief_schema_drift` writes one JSON object per call, carrying the
   whole `problems` array (`bundlebees_plugin/contract_drift.py:49-63`). The
   existing contract gate writes one line per finding with `code`/`error`/`field`
   (`bundlebees_plugin/tools.py:607-624`). Observable behaviour 4 and AC-003 say
   "one JSON object per call", which this matches, but AC-005's parenthetical and
   the CHANGELOG say "one JSONL line per finding". Only the wording is
   inconsistent for the multi-problem case; the shipped test and the frozen
   observable behaviour both require per-call. No gate or behaviour defect.
   Suggest aligning the AC-005/CHANGELOG sentence in a follow-up.

2. **Frozen-schema conditional adds a spurious `contract` problem (out of slice).**
   `bundlebees_plugin/schemas/rizzstack-brief.schema.json:193-208` has an
   `if`/`then` whose `if` does not require `risk`, so a document that omits
   `risk` also produces `$: missing required property 'contract'` (see probe 3).
   The file is the frozen, digest-pinned vendor copy, so this is not a B8 defect;
   it is disclosed because B6 enforcement will consume the same findings. It does
   not break AC-002 (which only requires a list and a named offending field).

## Contract trace: can drift refuse, abort or delay a dispatch?

No. In `bundlebees_plugin/tools.py`, `client.create` runs at line 961 and
`_dispatched` is only called after it at line 975. The drift check and record
run inside `_dispatched` at lines 495-499, after the launcher create and after
every gate. `check_brief_drift` catches every `Exception` and converts it to a
problem string (`contract_drift.py:18-29`); `record_brief_schema_drift` catches
every `Exception` and returns `recorded=False` with a bounded `error`
(`contract_drift.py:62-65`). A `None` state dir or an empty finding list returns
the block without writing (`contract_drift.py:46-48`). The envelope block is
only added when findings exist (`tools.py:496`), so a clean brief is unchanged.
A recording failure therefore cannot change the gate outcome, refuse, or raise;
it can only delay the success response, not the launcher create.
