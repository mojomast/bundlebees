# Opt-in index for Rails attempt reads

On local ledgers with many attempts, each capped R12 continuation scans up to 2,001 matching envelopes to classify the context. SQLite can serve this scan from an expression index on the attempt ID and ingestion sequence with the existing metadata. The reader still loads and authenticates the candidate envelopes, checks their canonical bytes, and computes coverage and projection for each request. The index does not change cursor or wire formats. It is intended for local `attempt` drilldown; the imported-row query plan and other selectors were not benchmarked.

This is an **offline maintenance operation**, not part of startup or an HTTP route. All writers, readers, backup and restore tools that use the resulting database must have compatible SQLite builds: in particular, `json_extract` must be available and accepted in schema expressions with `trusted_schema=OFF`. Tested with SQLite 3.46.1. Do not weaken `trusted_schema` for an older client. Keep an index-free backup before changing an existing deployment.

1. Stop other ledger users. Confirm the local ledger path and expected UUID from the configuration/health record. Use a private, disk-backed temp directory on the ledger volume for SQLite's index sort.
2. Run `SQLITE_TMPDIR=/absolute/private/temp python3 scripts/rails_attempt_index.py /absolute/rails.sqlite --ledger-uuid EXPECTED-UUID`. The tool opens an existing WAL ledger read/write, checks the expected identity under the writer lock, and creates one fixed index transactionally. It refuses a busy writer, a conflicting index, more than 120,000 existing event rows, a database larger than 512 MiB, or less than 1.5 GiB free on the ledger volume. A SQLite progress handler interrupts long builds after approximately ten seconds of VM execution. An identical index is a no-op. A new **empty** initialized ledger can be indexed before first append.
3. Verify the normal hardened reader and a representative append on a copy before deployment. Every future local event adds one index entry. To revert the read plan, stop ledger users and `DROP INDEX rails_local_attempt_scan` in an offline write transaction on the verified ledger. Freed pages can be reused; no vacuum is required.

On a private copy of the 100k fixture with 106 additional committed observations, the index added 15,212,544 bytes and built in 716 ms. Authenticated R12, 100 warm logical 500-row queries per surface on that indexed fixture: p95 470.575 ms (events), 184.800 ms (view). This does not guarantee 500 ms at other loads: a separate profiled 10-sample run had a 631.511 ms events tail. Unindexed measurements remain applicable to default ledgers. Record the index configuration explicitly when qualifying a run.
